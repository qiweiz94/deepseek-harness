# @deepseek-ai/dsh-plugin-pinned-scratchpad

[English](README.md) | 中文

面向模型的 `scratchpad_update` 工具，以及固定注入的 `<agent_scratchpad>` 提示词块：一个由模型自己维护的小型键值存储，在每一轮对话之前都会在硬性 token 预算下重新渲染进系统提示词，因此模型选择保留的事实能够在对话压缩（compaction）后继续存在。

## 功能

在 `ctx.tools` 上注册一个工具，并在 `ctx.systemPrompt` 上注册一个有序分节：

- `scratchpad_update(key, value)`：当 `value` 为字符串时设置或替换某个键，当 `value` 为 `null` 时删除该键。返回结果为 `{ key, action, entries, dropped }`，其中 `action` 为 `set`、`deleted` 或 `missing`（删除时未匹配到任何键），`entries` 是本次调用后固定的键数量，`dropped` 是当前因 token 预算而未在提示词块中显示的最旧条目数量。
- `agent:scratchpad` 提示词分节将固定条目渲染为 `<agent_scratchpad>` 块。它的文本是一个 **provider**，因此每次装配都会基于存储的实时状态重新求值。当没有任何内容被固定时，该分节渲染为空字符串，`renderPrompt` 会将其丢弃——标签不会出现在空白便笺之上。

## 注入接缝（以及对规格说明的一处更正）

**本代码库中并不存在 `prompt/construct` 钩子。** 构建规格假设了它的存在；但无论在 `packages/cordis`（`vendor/cordis`）、`packages/core` 还是代码树的其他任何位置，都没有这个事件。真正的提示词组装接缝是 `@deepseek-ai/dsh-system-prompt`：

- `ctx.systemPrompt.section({ name, order, text })` 注册一个有序贡献，其中 `text` 可以是一个函数，在每次装配时以该次装配的 `AssembleContext` 求值。
- `SystemPrompt.assemble()` 解析全部 provider，然后运行 `system-prompt/assemble` 瀑布流，其返回值具有权威性。

本插件注册的是 **section**，并且刻意 **不** 添加 `system-prompt/assemble` 监听器——两者都会在每次装配时运行，同时使用会导致该块被注入两次。瀑布流是变换用的逃生舱口，而不是贡献接缝。

### 为什么 section 才是不可压缩的选择

`ctx.systemPrompt` 提供两种贡献形态，其中只有一种处于压缩机制触及不到的地方：

- `section()`——属于 **系统提示词**，每次装配都从注册表重建。渲染出的文本从不进入会话事件日志。
- `context()`——动态运行时上下文，会 **以持久的 user 角色快照形式落入** 消息历史。

压缩（`@deepseek-ai/dsh-compaction`）修剪并检查点化会话事件日志。分节的文本是在装配 **过程中** 产生的，从不写入该日志，因此压缩没有任何属于我们的内容可以移除；下一轮会重新读取实时存储并以完全相同的方式重建该块。这就是全部机制——该块并非「受保护而免于」压缩，而是根本不存在于压缩所操作的材料之中。若改用 `context()`，反而会把该块恰好放在压缩够得着的位置。

## Token 预算与淘汰

预算覆盖 **整个渲染块**——包含 `<agent_scratchpad>` 标签与截断标记行，而不仅仅是条目行。成本按每 token 四个字符估算（`estimateTokens`）；本框架未提供分词器服务，且每次装配都发起网络往返的代价无法承受，因此该块采用这一惯用近似来计价。它对英文散文略微高估，从而使预算偏保守。

当该块无法容纳于 `maxTokens`（默认 250）时，条目会 **按写入时间从最旧开始** 被丢弃，并替换为一行标记，例如 `[2 earlier entries dropped: scratchpad token budget]`，以便告知模型它丢失了较旧的笔记，而不是让其无声消失。这里有两个刻意的取舍：

- **顺序取决于写入时间的新近程度，而非首次插入顺序。** 重写某个键会将其移动到最新位置，因此模型持续更新的笔记永远不会成为被淘汰的那一个。
- **条目绝不会被部分渲染。** 单个过大的值会被整体丢弃并计入标记，因为半条笔记是具有误导性的笔记。如果连标记本身都无法容纳，该块将渲染为空字符串——预算被绝对地遵守，而非近似地遵守。

`maxValueBytes` 上限（默认 4,000 个 UTF-8 字节）会在工具边界处拒绝过大的单次写入，因此一次糟糕的写入无法把整个便笺挤出提示词。

## 导出形态

函数/命名空间插件：导出 `name` / `inject` / `apply`，且没有 default 导出。多余的 `export default` 会通过 Loader 的 `unwrapExports` 使模块坍缩并丢失 `inject`（参见 [docs/postmortem/0001](../../../docs/postmortem/0001-acp-default-export-drops-inject.md)）。

## 模型体验

### 工具 schema

#### 模型看到什么

一个必填的 `key` 字符串，以及一个必填的 `value`——它是一个双分支联合类型：字符串（笔记文本）或 `null`（删除该键）——外加结构化结果对象 `key`、`action`（`set` | `deleted` | `missing`）、`entries` 与 `dropped`。插件配置（`maxTokens` 默认 250，`maxValueBytes` 默认 4,000）在加载时校验，遇到非法值会显式失败；它不改变任何 schema 字段，只影响调用是成功返回还是返回一个指示性的错误结果。

工具描述直接把淘汰规则告知模型——最久未写入的条目最先被丢弃，重写某个键会刷新它——因为淘汰顺序只有在模型能够据此规划时才有用。

#### Token 影响

在该工具可见的每个请求上都有固定的 schema 成本，另加该块自身：至多 `maxTokens`（250）个估算 token，而在没有任何内容被固定时恰好为零。

#### KV 缓存影响

该块是系统提示词中最易变的文本，因此注册在 order 200——位于框架身份（-100）、部署人设（0）与工具指引区间（100–199）之后。这使得排在它之前的每个稳定分节在各轮之间保持逐字节一致。任何写入仍会使从该块起往后的前缀失效；这一成本是可变固定块所固有的，而将其放在最后正是把成本限制在该块自身尾部的原因。

## 已知限制与后续工作

- **`complete` 提示词分节会抹除该块。** `assemble()` 会将生效的 `complete: true` 分节还原为 **唯一** 的提示词分节，丢弃其他所有贡献——包括本块。这是提示词注册表的性质，而非本插件的性质，且对 `section()` 与 `context()` 同样适用。
- **估算 token，而非精确计数**——每 token 四字符的启发式只是近似。该块可能低于 250 个真实 token；它不应显著超出，但对非英文文本或密集标识符而言这一界限并不精确。
- **仅存于内存**——便笺的生命周期与插件 fiber 相同。它能在压缩后存活，但无法在进程重启后存活，也不会持久化到会话日志。
- **尚无按 agent 的作用域隔离**——每个插件实例一个存储。通过带作用域的上下文注册可以遮蔽该分节，但由同一实例挂载的同级 agent 会共享一个便笺。
- **仅支持整值写入**——没有追加或打补丁操作；模型需重写键的完整值来修改它。
- **多行值按原样渲染**——包含换行的值会在块内跨越多行，`key: value` 的行格式不会对其进行转义或缩进。
