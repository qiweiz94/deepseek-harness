# Agent Note: Settings persistence closes five correctness gaps and gains durable atomic writes

Status: implemented

English | [中文](2026-08-20-settings-persistence-correctness-and-durability.zh.md)

## Problem

`@deepseek-ai/dsh-settings` and its shared `@deepseek-ai/dsh-atomic-write` primitive carried five open `TODO`s and one durability gap, each capable of corrupting or leaking settings state without ever failing loudly:

- **Prototype-shaped keys** (`settings-json-properties`): `cloneJsonShaped`, `mergeLayers`, `applyPathOp`, `deepEqualJson`, and the redaction walker read and wrote dynamic keys through plain property access. A parsed document section keyed `"__proto__"` did not survive as data — the assignment reparented the object being built instead of storing the key — and a path op that unset an absent `"__proto__"` path read `Object.prototype` as if it were a child section.
- **Watcher quiescence** (`settings-registration-quiescence`): a registrant's watcher callbacks were not drained on fiber disposal. A watch invocation already in flight, or one queued moments before disposal, could still run — or still be running — after the registrant's disposer had returned, so code downstream of "this fiber is gone" observed a callback anyway.
- **Replacement resync** (`settings-replacement-resync`): when a registrant was replaced while a write was in flight, the replacement's resolved value was still the one read from the pre-write document. The write's own persisted section was silently dropped from the replacement's view until the next unrelated write happened to refresh it.
- **Wire redaction** (`settings-wire-redaction`): `redactSecrets` only walked `object`/`dict`/`array` schema nodes. A `role('secret')` field reachable solely through a `union`, `intersect`, `transform`, or `tuple` node was returned verbatim with nothing recording that the walker had missed it — a schema author could believe a field was redacted when it was not.
- **Namespace vocabulary** (`settings-namespace-vocabulary`, left open): `SettingsDescriptor.ns` predates the settled `namespace` vocabulary used elsewhere in the public API. The field is wire-visible (`SettingsNamespaceView` and the write-request payloads in `dsh-host-apiproxy`'s RPC surface) and read directly by six-plus `dsh-client-*` packages plus the generated `gen-cordis-api` catalog entry for `SettingsDescriptor`. A clean rename spans all of those together with this package; see Alternatives considered.
- **Atomic-write durability**: `writeFileAtomic` committed its rename with no `fsync` of either the temp file's content or the parent directory entry, so a crash between a successful `rename()` and the OS actually persisting either could unwind the replacement, even though every reader that observed the rename already saw complete content.

## Decision

**Own-property keys.** The four mutating helpers and the redaction walker now use `Object.hasOwn` for presence checks and `Object.defineProperty(..., { enumerable: true, writable: true, configurable: true })` for writes wherever a document-supplied string becomes a property key, instead of `in`/bracket assignment. A key like `"__proto__"`, `"constructor"`, or `"__defineGetter__"` is thereafter indistinguishable from any other string key: it is cloned, merged, patched, compared, and redacted as data, and it can never reparent or otherwise mutate the object literal being built.

**Drain on disposal.** The registration effect's disposer now deactivates every one of the registrant's active watchers before returning and awaits each watcher's already-started invocation tail. A callback invocation is either fully complete or never started by the time disposal resolves; nothing straddles the boundary.

**Re-resolve from the persisted section.** A write that commits while its registrant is being replaced now re-resolves the replacement registration from the just-persisted document section — not the document snapshot the replacement was originally registered against — bumps the replacement's revision, and publishes from that resolution. A persisted section the replacement's schema or `validate` rejects keeps the replacement's last good value and warns, exactly matching the normal publish path; there is no separate degraded case for "replaced mid-write."

**Fail closed on unreachable secrets.** `redactSecrets`'s walker gained a `declaresSecret` subtree check and a `guardMismatch` fallback. Any node the walker does not structurally traverse (`union`, `intersect`, `transform`, `tuple`, and any future node kind) now throws when a `role('secret')` field is declared anywhere beneath it, naming the unreachable path in the error — the walker cannot locate the secret inside that shape, so it refuses to redact rather than pass the value through unredacted. Separately, a present value whose node is `object`/`dict`/`array` but whose runtime shape does not match (a record where an array was declared, for instance) is stripped and its container position recorded in `secrets`, rather than passed through untouched: the walker cannot descend into a shape mismatch either, so the same fail-closed rule applies at the leaf as at the unsupported-node case. A schema with no declared secrets keeps its previous verbatim pass-through in both situations — the new checks cannot fire where there is nothing to protect.

**Durable atomic writes.** `writeFileAtomic` now opens its temp sibling directly (`open(temp, 'wx', mode)`) instead of using the one-shot `writeFile` helper, writes the content, and calls `handle.sync()` before closing and renaming; a sync failure aborts the write exactly like a write failure already did (temp removed, error rethrown), so a crash can never promote content the device never received. After the rename commits, a new `fsyncParentDirectoryBestEffort` helper opens the parent directory read-only and syncs it, but — unlike the content sync — swallows both the open and the sync failure instead of propagating them: the rename has already committed the new content under its final name by that point, so a directory-entry-durability failure does not change whether the write succeeded, only how quickly a subsequent crash's recovery would observe it. `withFileLock`'s lock-file write is unchanged; it does not need content durability, only the existing `wx` exclusivity.

## Alternatives considered

- **Namespace vocabulary — do the rename now.** Rejected for this PR: the field is wire-visible and its consumers span `dsh-host-apiproxy`'s general RPC handling, the generated `dsh-tool-cordis` API catalog, and six-plus `dsh-client-*` packages, none of which are in this change's ownership. Editing them here would touch files another concurrent lane may hold open and would mix an unrelated rename into a correctness-and-durability PR. The `TODO` stays, now naming the full blast radius so a dedicated cross-package change can pick it up directly instead of rediscovering the scope.
- **Prototype-shaped keys — sanitize/reject `__proto__` at the document boundary instead.** Rejected: a document author choosing `"__proto__"` as a namespace-internal key is unusual but not invalid JSON, and rejecting it would make the store's behavior depend on a key blocklist that has to be kept in sync with every future dangerous-key discovery. Own-property access closes the whole class (any key that collides with an `Object.prototype` member) without an enumeration.
- **Watcher quiescence — let in-flight invocations race disposal and rely on callers to check liveness.** Rejected: it pushes a correctness requirement (`hasSettled` before acting on a callback) onto every current and future watcher, for a guarantee (no callback after disposal) the registry can provide once, centrally.
- **Replacement resync — republish only on the next unrelated write.** Rejected: it leaves an arbitrarily long window (until *something else* writes) during which the replacement's resolved value silently disagrees with the persisted document, with no signal that a resync is pending.
- **Wire redaction — enumerate every schema node kind that can appear and add container support for `union`/`intersect`/`tuple`.** Deferred, not rejected outright: full traversal support for those node kinds is a larger schema-walking change with its own design space (which union branch does a value belong to when only the runtime value is known?). Failing closed today converts a silent leak into a loud, fixable registration-time or write-time error, which is the correctness property this change needed; broader traversal remains open future work.
- **Atomic-write durability — fsync the directory fail-loud, matching `dsh-storage-json`'s `writeAtomic`.** Rejected for this shared primitive specifically: `dsh-storage-json`'s backend has exactly one writer per process and can afford to fail a write outright on a directory-fsync failure. `dsh-atomic-write` is consumed by the user-settings document and the credentials store across arbitrary host filesystems (including network mounts) and platforms (Windows cannot open a directory read-only the way this helper does); failing the whole write because the *directory-entry* fsync — a crash-recovery narrowing, not a correctness requirement — could not complete would turn an availability non-issue into a write failure on exactly the filesystems least able to tolerate one. The content fsync stays fail-loud because its failure means the data may genuinely be unwritten.
- **Atomic-write durability — reopen the temp file after `writeFile` instead of switching to `open`+`handle.sync()`.** Rejected: an extra open/close round trip for no benefit over holding the handle already open from the initial `wx` create.

## Consequences

- A settings document section, credentials-store record, or path-op target can use any string key, including one that collides with an `Object.prototype` member, without corrupting the object being built or exposing prototype properties as if they were stored data.
- A disposed registrant's watchers are provably quiescent: `tests/settings.spec.ts` disposes a fiber mid-invocation and asserts no further callback runs and the disposer does not resolve until the in-flight one finishes.
- A registrant replaced during an in-flight write always resolves from that write's persisted section on the next read, matching what publish would have produced had the replacement been registered before the write started.
- A misconfigured secret schema (one where a `role('secret')` field sits behind a node kind the walker cannot traverse) now fails registration or the offending write with a specific error naming the unreachable path, instead of silently shipping the secret's value over the wire. `tests/redact.spec.ts` exercises the union/intersect/tuple cases, a structurally untyped node (outside what any current schemastery construct produces, but not excluded by the walker's structural `SchemaNode` contract), and the object/dict/array shape-mismatch cases as known-bad inputs.
- `writeFileAtomic` callers get crash-durable content by default with no API change: a device that never received the fsynced bytes now surfaces as a rejected write instead of a rename that silently unwinds on the next crash. `dsh-atomic-write/tests/atomic-write.spec.ts` forces a content-fsync failure (rejects, temp removed, target absent) and a directory-open failure and a directory-fsync failure (both resolve normally, target holds the new content) via a `FileHandle.prototype.sync` spy and a `node:fs/promises` `open` mock, matching the existing `dsh-settings-file`/`dsh-credentials-local` real-composition suites, which were updated to inject their simulated temp-write failure through `open()` rather than the no-longer-called `writeFile()`.
- The settings-namespace-vocabulary rename remains open, now with its consumer inventory recorded in the source comment so the next change does not need to rediscover it.
- `dsh-settings`'s own scoped test suite reaches the package's per-file 100% coverage gate on its own: `installSettingsSection`'s `validate`-hook forwarding branch and `redactSecrets`'s untyped-node branch predate this change (present since the wire-redaction and registration-quiescence fixes landed) but had no direct test; both are now covered directly instead of relying on cross-package exercise.
