# Agent Note：语义符号主体补丁插件

Status: implemented

[English](2026-08-20-plugin-semantic-patcher.md) | 中文

## Problem

替换一个函数或方法的主体是最常见的编辑之一，但文本匹配的编辑工具（`str_replace`、`edit`）要求模型精确复现周围的字节，一处细微偏差要么失败，要么更糟——当同一段文本出现两次时补到了错误的位置。没有一个编辑能按符号命名并无视周围文本替换其主体，也没有一个能拒绝写入无法解析的结果。

## Decision

`@deepseek-ai/dsh-plugin-semantic-patcher` 注册 `patch_symbol_body({ path, symbol, newBody })`。它用 tree-sitter 解析文件，在语法树中定位具名符号（顶层函数、箭头函数值绑定，或 `Class.method` 成员），并恰好替换那段主体。匹配零个或多个符号的名称会失败并列出候选，而非猜测。替换在写入之前先解析：无法解析的结果让文件逐字节保持不变。写入受约束——`resolve(root, path)` 加上拒绝 `..`/绝对路径的相对路径检查（`patcher.ts`），因此逃逸到仓库根之外的路径在任何写入之前被拒绝，写入是原子的且保留原始 mode。它只注入 `tools`。

该插件从并行分支（`feat/plugin-semantic-patcher`）到来时没有 Agent Note；本笔记在集成时补齐，插件已在当前 master 上以标准集成接线重建。

## Alternatives considered

**在文本上匹配替换（现有编辑工具的做法）。** 需要精确的周围字节，并悄然冒着补到错误位置的风险；语法树查找按身份定位声明，这正是关键所在。

**先写后校验。** 写入无法解析的主体再回滚，会留下磁盘上文件损坏的窗口（该窗口内崩溃会持久化损坏）；在写入前解析替换意味着文件从不处于损坏状态。

## Consequences

模型可以按名替换符号主体，并保证编辑落在正确的声明上、从不让文件无法解析或写到仓库之外。它处理常见的符号种类（顶层函数、箭头绑定、类成员）；其他构造（重载、嵌套闭包）超出范围并带候选列表失败即报错。超过 `maxBytes`（默认 2 MiB）的文件被拒绝。
